# Code of Conduct

Setlist is a small project with one maintainer. This is short on purpose, but it is not
decorative — it is what will actually be enforced.

## The standard

Be decent to people. Concretely, that means:

- Criticise code, not the person who wrote it. "This drops the error" is useful. "This is
  amateur work" is not, and says nothing the first sentence didn't.
- Assume the other person is competent and acting in good faith until you have real evidence
  otherwise. Most disagreements here are two people holding different context.
- Take a "no" without relitigating it. Not every good idea belongs in this project, and a
  maintainer declining something is not an insult.
- Harassment, personal attacks, and unwelcome attention aren't welcome, and neither is
  demeaning anyone for who they are. That includes doing it in a way you could later call a
  joke.

If you are frustrated with the software, say so plainly — "this is confusing" and "the README
is wrong" are welcome, as [CONTRIBUTING.md](CONTRIBUTING.md) says. Frustration aimed at the
code is fine. Frustration aimed at a person is not.

## Scope

This applies in the issue tracker, in pull requests and reviews, in commit messages, and
anywhere else this project's spaces reach.

## Reporting

If someone's behaviour here is a problem, tell the maintainer. This repository's only private
channel is GitHub's private vulnerability reporting — the **Security** tab, then **Report a
vulnerability**. It is meant for security bugs, but it is a private thread the maintainer can
read, so use it for this too and say up front that it's a conduct report rather than a
vulnerability.

**If the maintainer is the problem,** don't route it through the maintainer. Use GitHub's own
[report abuse](https://github.com/contact/report-abuse) form, which goes to GitHub Support
rather than to this repository.

## What happens then

Reports are read privately and are not shared beyond what is needed to act on them. Depending
on what happened, the response is a private word, an edited or deleted comment, or a block from
the repository. There is no committee and no appeals process — there is one maintainer, who
will try to be fair and will sometimes get it wrong.

## Attribution

The spirit of this is the [Contributor Covenant](https://www.contributor-covenant.org), stated
in fewer words and with an enforcement route that a one-person project can actually honour.
